Security review on April 24 2026 of the Renvoo memory CLI and marketing site on branch codex/renvoo-website-foundation. Dependency audit found zero known npm vulnerabilities and no committed secrets; .env files are ignored. Main findings: the ingest command accepts arbitrary URLs and auto-downloads page images without protocol, host, IP, timeout, or size restrictions, so it can be abused as an SSRF and resource-exhaustion primitive against the machine that runs it; ingest also sends full source text and surrounding memory context to OpenAI and full chunked source text to Pinecone whenever those keys are configured, with no redaction gate or confirmation step for sensitive clinic or internal documents; Pinecone data requests trust the cached host from memory/archive/cache/pinecone-index.json and then attach the live Api-Key header, so a poisoned cache file could redirect archive traffic and exfiltrate credentials; the public site loads Google Fonts from fonts.googleapis.com and fonts.gstatic.com on every page and the hosting configs set only Referrer-Policy, nosniff, and X-Frame-Options, so there is no Content-Security-Policy and visitor metadata is disclosed to Google. Verification during the audit: npm audit showed zero vulnerabilities, npm run build passed, npm test passed, and npm run site:build passed. Recommended fixes: restrict ingest URLs and asset fetches to allowed schemes and public hosts, add request timeouts and size limits, add a sensitive-source export warning or redaction step before OpenAI or Pinecone upload, validate cached Pinecone hosts against expected domains before sending Api-Key, self-host fonts or switch to local assets, and add a CSP in Vercel and Netlify configs.
